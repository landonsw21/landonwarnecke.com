# landonwarnecke.com — how this site is built and published

Static portfolio for Landon Warnecke (industrial design, Western Washington University; the site shows the name "Landon Warnecke"). No build step: plain HTML/CSS/JS.

## Files
- `index.html` — the whole site, pre-rendered (projects, extras, gallery, resume, contact). GENERATED by `_src/build.py`, as are `site.css` and `site.js`: never hand-edit these three, change `_src/` and rebuild.
- `_src/` — the site generator (plain Python 3, no packages):
  - `content.py`: all text and image lists (a project's card `line` is a 2–3 word summary on one line with its name, except Bubble and Vivarium which keep longer lines; the details row's `Type` is a 5–8 word summary; each project's other details categories were picked by Landon, so ask before adding or removing any; no course numbers or dates; longer description goes in its first section) (bio, projects and their case-study sections, gallery, extras, resume, contact links, Turnstile site key, `HERO_FOCUS` = which band of each card image shows while collapsed).
  - `build.py`: turns content.py into index.html + site.css + site.js. Run `python3 _src/build.py` from the repo root.
  - `base.css`: base styles; build.py appends its own overrides and swaps hex colors for `var(--lw-*)` tokens.
  - `images.py` (needs Pillow): `heroes` regenerates the project card images (full frames, one product; cards show a 384px band while resting (hover only undims and outlines it), the whole image when clicked) from the ID copy folder; `add KEY SOURCE [--width N] [--rotate DEG] [--flip]` (--flip mirrors left to right) exports any photo/render/HEIC/PDF page into portfolio-media; `sheet KEY COLS SOURCE...` tiles drawing pages into one image; `cut KEY PROJECT/file.dxf` turns a laser-cut DXF into an SVG drawing (build.py shows portfolio-media .svg files like photos). In a case-study section, a section's last value is its image columns (1, 2 or 3; phones always show 1), and an image given as (key, alt, "wide") spans all of them (e.g. MOAI's final: one large render, three details below). Images always stay in the section's body column, never under the subheadings column. `label KEY` draws part labels (Manrope from `_src/tools/fonts/`, OFL license) onto a render from `_src/labels/KEY.json` (used for Bubble's exploded view; move a label by editing its `y` or `at`, then rerun). Source folder: ~/Downloads/Claude/ID copy (override with LW_ID_COPY).
  - `fisheye.py`: builds `editor.html` (Fisheye Studio) from Landon's studio source in ~/Documents/GBD/cube export (override with LW_FISHEYE_SRC): embeds studio-shell.html + its scripts like the studio's own build_editors.py, maps every color to theme.css, trims filler text, and copies `cube export.py` to `downloads/cube-export.py` for the Download KeyShot script button. After updating the studio there, run `python3 _src/fisheye.py`; it stops and names anything it can't find, and lists any new color that needs a token.
  - `pdfimg.py`: pulls images embedded in a PDF at their own resolution (no slide layout or slide text). `python3 _src/pdfimg.py deck.pdf OUTDIR` dumps them as ..._OBJ_WxH.png; then use `PDFIMG:PROJECT/deck.pdf:OBJ` as an images.py source. Prefer original photos/scans, then PDF-embedded originals; never a flattened slide.
  - `images.py sheet ... --photos` builds a moodboard/reference board from whole photos (tight gaps in the panel colour). Palettes are HTML, not images: `<span class="lw-palette"><span class="lw-sw"><i style="background:#hex"></i><b>Name</b><small>Pantone · words</small></span>…</span>` in a section paragraph.
  - `tools/pdfpages.swift`: renders PDF pages (compiled automatically by images.py).
- `site.css`, `site.js` — styles and interactions (on desktop the left column is one fixed 256px column with the original contents and order; inside it the photo (80x100) and name (two lines) lead, then tabs, then About me as a muted caption, then the footer; it never changes size; clicking an open project's text or background closes it, images/links/section bar excepted; case-study headings sit above their content in one column on every screen; on phones the header is one row: photo, name and an arrow; tapping it drops a menu with About me and the tabs over the page, so inside a project only the section bar sits under it; tabs, where clicking the current tab collapses an open project; one-at-a-time project drawers with sticky chapter bar; the gallery's tile grid, where each tile in content.py's GALLERY opens the lightbox at its first piece; lightbox with Esc/arrow keys; deep links like `#gallery` or `#axio`).
- `portfolio-media/` — optimized images (KeyShot renders and original photos from the ID folder). Also used by the Framer copy of the site.
- `theme.css` — THE palette. Shared by the portfolio, Fisheye Studio and Perspective Studio. Change colors here only.
- `editor.html` (GENERATED by `_src/fisheye.py`, never hand-edit) + `downloads/cube-export.py` — Fisheye Studio, linked from Extras: rings, pins, optics, animation timeline, PNG export, KeyShot script download. Colors come from theme.css (including the WebGL demo scenes via `--lw-scene-*`).
- `perspective-studio/` — Perspective Studio (moved from landonsw21.github.io/perspective-studio). Its UI colors map to theme.css; its drawing colors (VP rays, guides) are functional and intentionally not themed.
- `_redirects` — Cloudflare Pages short links: `landonwarnecke.com/linkedin` forwards to the LinkedIn profile (the Contact page shows that short address but links to LinkedIn directly).
- `_headers` — Cloudflare Pages headers. Only `site.css`, `site.js` and `portfolio-media/*` get a long cache, because index.html links them as `?v=<content hash>` (build.py does this for every CSS/JS/image link). Never add long caching for unversioned files: Cloudflare's edge on landonwarnecke.com honours it and keeps serving stale copies after a deploy.
- `contact-worker/` — the Contact form mailer, a separate Cloudflare Worker (`landonwarnecke-contact`) deployed by Workers Builds from this folder and routed at `landonwarnecke.com/api/contact` (Pages Functions can't send email). It checks Cloudflare Turnstile, then emails the message through Email Routing from contact@landonwarnecke.com with Reply-To set to the visitor. Secrets live only in the Worker's dashboard settings: `TURNSTILE_SECRET`, `CONTACT_TO`. The public Turnstile site key is in the form's `data-sitekey` (index.html). The form never says where messages are delivered.
  - Both secrets must be **Runtime** secrets of type **Secret** (Worker → Settings → Runtime variables and secrets). Build variables are invisible to the running Worker, and plain Text variables get wiped by every deploy.
  - Debugging: Worker → Observability → Events logs each POST; a Turnstile rejection logs Cloudflare's error codes (e.g. `invalid-input-secret` = wrong TURNSTILE_SECRET). Turnstile always fails inside automated browsers (e.g. the Claude app's browser pane), so test in a normal browser.
  - Workers Builds settings: root directory `contact-worker`, deploy command `npx wrangler deploy`, no build command.

## Image order (every project)
1. The card photo is the project's highest-fidelity, most context-giving picture of the final model.
2. The case study then starts from the brief and rough sketches and climbs in fidelity section by section and within each section. Fidelity means how resolved the design is, not the medium: refined sketches come after rough cardboard or foam models and before the final model (e.g. MOAI: thumbnails, cardboard and pink foam models, refined sketches, yellow foam model, renders).
3. Final-model photos and renders appear only at the end, in Final (never in the Overview or brief).
4. Check every sketch and scan is upright before adding it: titles and notes read left to right, products stand on their bases. Many scans and phone photos of sheets come in sideways; fix with `images.py add ... --rotate 90` (or 270), never by rotating the web copy.

## Design system
Proportions (keep every new value on these; base.css says the same at the top):
- Spacing: 4, 8, 12, 16, 24, 32, 48 px (120 only for the page bottom). Gaps between cards/tiles and the inset of everything inside a card, project drawer or tile: 24 desktop, 16 phones (the drawer's 1px border is counted, so its padding is 23 / 15). Page edges: 32 top, 48 sides desktop; 16 phones. Case-study sections 48 apart (32 phones).
- Text: 12 (mono labels), 14 (secondary, chips, buttons in cards), 16 (body, tabs, card lines), 20 (name, resume headings, contact links), 24 (section and card headings), 30 (project card titles). Side-by-side section headings sit on the baseline of their first text line.
- Corners: 10 for controls, images, inputs and the portrait; 18 for cards, drawers, tiles and extras. Touch targets 44-48 tall.
- Inside an open project the title on the photo, the section chips, the docked title and the text all share one left edge (site.js docks the title at the bar's padding).
Greige + Pomegranate, defined once in `theme.css` as `--lw-*` custom properties (light set + dark set).
- The portfolio forces the light set (`<html data-theme="light">`); the tools follow the visitor's system light/dark setting.
- To change the palette: edit the values in `theme.css` (both the light block and the two identical dark blocks), commit, push. Keep text contrast at 4.5:1 or better.
- site.css, editor.html and perspective-studio/index.html must use `var(--lw-…)`, never raw hex (exceptions: functional drawing colors and JS fallbacks).
- Never use Fisheye lime (#D4F28A / #d5f596) or green-black (#101210).

## Publishing workflow
1. Change content/design in `_src/` (ask Landon before new design or interaction decisions), then `python3 _src/build.py`.
2. Commit to `main`.
3. Push (GitHub Desktop → Push origin, or CLI once credentials are set up).
4. Cloudflare Pages deploys `main` automatically to https://landonwarnecke.com (build command: none, output directory: `/`).
   GitHub Pages also serves the repo at https://landonsw21.github.io/landonwarnecke.com/ (useful for previews).
